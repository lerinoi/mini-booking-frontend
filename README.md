# Mini Booking — frontend

Страница бронирования одной переговорной: выбор даты, девять часовых слотов с 09:00 до 18:00, создание и отмена встречи без перезагрузки страницы.

## Стек

Vue 3, Composition API, `<script setup>`, JavaScript, Vite, PrimeVue 4 и PrimeIcons. Запросы выполняются через Fetch API; Pinia, Vuex и Axios не используются. В Docker установлен Node.js 22.

## Запуск

Нужны Git, Docker и Compose v2. Локальный Node не требуется. На Windows запускайте команды в WSL 2 с включённой интеграцией Docker Desktop. Разместите два отдельных репозитория рядом:

```text
mini-booking/
├── backend/     # Laravel и compose.yaml
└── frontend/    # этот репозиторий
```

Из `mini-booking/backend`:

```sh
docker compose config --quiet
docker compose up -d --build --wait
docker compose exec backend php artisan db:seed --force
```

Откройте http://localhost:5173. API доступен на http://localhost:8000/api/slots. Порты 5173 и 8000 должны быть свободны. До запуска Seeder расписание пустое. Повторный запуск Seeder безопасен: он дополняет расписание, сохраняя историю.

Compose собирает frontend из `../frontend`, устанавливает зависимости командой `npm ci` из `package-lock.json` и запускает Vite. Исходники подключены через bind mount, `node_modules` — через отдельный volume. Изменения исходников подхватываются без пересборки. Переменные окружения frontend для локального запуска не нужны; backend создаёт свой `.env` автоматически.

Остановить приложение можно командой `docker compose down` из `backend`. Не добавляйте `-v`, если хотите сохранить volumes зависимостей. Полная инструкция по базе и окружению находится в README backend.

## Интерфейс и API

Фильтр содержит даты загруженного расписания. Карточки показывают статусы «Свободен», «Занят», «Прошёл». Дата и время форматируются через `Intl.DateTimeFormat` с явным `timeZone` из API, независимо от часового пояса браузера. Сетка адаптируется под ноутбук, планшет и телефон.

Свободный будущий слот открывает PrimeVue Dialog с датой, временем, именем и email. Форма проверяет обязательные поля и формат email, блокируется на время отправки, показывает ошибки Laravel под полями. Успех закрывает форму, показывает Toast и обновляет расписание.

Активное бронирование можно отменить после подтверждения в ConfirmDialog. Будущий слот снова становится свободным; прошедший остаётся прошедшим. В демо нет авторизации и проверки владельца бронирования.

Запросы собраны в `src/composables/useBookings.js`:

- `GET /api/slots` — расписание;
- `POST /api/bookings` — создание;
- `DELETE /api/bookings/{id}` — отмена по `active_booking_id`.

Vite проксирует `/api` на `http://backend:8000` внутри Docker, поэтому браузер использует тот же origin и не требует настройки CORS. Preview после сборки сам по себе API-прокси не предоставляет; для полного приложения используйте Compose с Vite dev server.

Для `422` выводятся ошибки полей; `409` и `404` при отмене обновляют расписание. Для `503`, `500` и сетевых ошибок отображаются сообщения с возможностью повтора. Запросы ограничены таймаутом 15 секунд. При неопределённом результате POST перед повторной отправкой сверяется актуальное расписание. Данные также можно обновить кнопкой в панели расписания; автоматической синхронизации между браузерами нет.

## Проверки

Все команды ниже выполняются из `backend` при работающем Compose:

```sh
docker compose exec frontend node --test tests/bookings.test.js
docker compose exec frontend npm run build
```

Тесты используют встроенный `node:test`: проверяют часовой пояс, загрузку, HTTP-коды, повторы и потерю ответа POST с подменой Fetch. Это не замена браузерной проверке: основной сценарий — выбрать свободный слот, забронировать, увидеть «Занят», подтвердить отмену, увидеть «Свободен» и забронировать повторно.

`npm run build` создаёт `dist`, исключённый из Git. `.env`, `node_modules`, логи и локальные данные также не коммитятся.
